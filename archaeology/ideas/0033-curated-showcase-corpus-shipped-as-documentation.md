# Curated showcase corpus shipped as documentation

## Problem

`cargo package` currently sweeps this repository's entire archaeology
into the crate: 114 of 167 packaged files are `archaeology/`, plus
`CLAUDE.md`, `.claude/`, `.github/`, `scripts/`, and `.scarp.toml` —
so an unpacked `scarp` crate is itself a Scarp repository. Henry's
decision on 2026-07-27 is to exclude it, implemented by
[[tsk_01KYJG0S7GY51W8M1WYFMEV7MQ|task 43]].

That leaves a real gap. The corpus is the most persuasive artifact
this project has — it is what proves the loop is used rather than
described — and after the exclusion nothing inside the published
crate demonstrates what a populated repository looks like. A reader
who runs `scarp init` sees an empty skeleton and has to imagine the
rest.

Shipping the real corpus is the wrong fix, and not only for size.
This repository's archaeology is a desire-path record: it bumbles,
backtracks, supersedes itself, and carries incident threads and
retrospectives that are honest history but poor pedagogy. It
demonstrates *that* the tool is used, not *how* to use it.

## Sketch

A small, deliberately authored corpus whose job is teaching, kept
distinct from the canonical record:

- one artifact per collection, each exercising the parts a newcomer
  will actually meet — a decision with consequences, an open dragon,
  a parked idea, a sprint owning two tasks in different states;
- at least one typed edge and one bound wikilink, so the reference
  model is visible rather than described;
- one deliberately broken artifact, if it can be isolated safely, so
  `doctor` has something to find and the error contract is
  demonstrable rather than theoretical;
- shipped where documentation lives rather than as canonical
  archaeology — an `examples/` tree, a docs page, or generated
  output — and clearly labelled as a fixture so it is never mistaken
  for this project's own record.

Open questions the eventual task must answer: whether the showcase is
hand-authored or generated by a recorded script (generated keeps it
honest and regenerable, hand-authored reads better); whether it is
verified by CI so it cannot rot against the real command surface;
and whether "documentation" means the crate tarball, docs.rs, the
README, or the repository only.

## Boundaries

Never load-bearing. No canonical artifact may cite the showcase as
evidence, no typed edge may target it, and deleting it must
invalidate nothing. It is a fixture and a teaching aid, not a second
corpus — and specifically not a place where project facts are
allowed to live.

It is also not a test fixture. Tests own their own temporary
repositories; a showcase that becomes load-bearing for the suite
would acquire exactly the coupling this boundary exists to prevent.
